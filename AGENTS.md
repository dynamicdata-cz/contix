# AGENTS.md – pravidla a kontext projektu CONTIX (pro vývojáře i AI asistenty)

CONTIX je GRC platforma (procesy, aktiva, rizika, kontroly, audity). Modulární monolit v TypeScriptu.
Dokumentace a UI jsou **česky**, kód, identifikátory a commit zprávy **anglicky**.

## Stack

Bun (runtime, pm, testy) · Hono (API) · Drizzle ORM + PostgreSQL · Zod (sdílené v `packages/shared`) ·
React 19 + Vite + TanStack Router/Query · Tailwind 4 + shadcn/ui styl.

## Příkazy

- `bun install` · `bun run dev` · `bun run typecheck` · `bun run admin:create <email> "<jméno>"`
- `bun test` (unit), integrační: `TEST_DATABASE_URL=postgres://contix:contix@localhost:5432/contix_test bun test`
- e2e: `E2E_DATABASE_URL=postgres://contix:contix@localhost:5432/contix_e2e bun run e2e` (DB *_e2e se vyprázdní)
- Po změně `apps/api/src/db/schema.ts`: `bun run db:generate` a pak `bun run db:migrate`. Migrace ručně neupravuj.

## Pravidla

- Nový modul API = `apps/api/src/modules/<modul>/routes.ts`, mount v `app.ts` (pod `protectedApi` = vyžaduje přihlášení).
  Modul zaregistruj v `MODULES` (`shared/modules.ts`), router začni `.use("*", requireModule(db, "<klíč>"))`,
  v menu podmiň `useModule()`.
- PATCH schémata tvoř přes `patchOf(CreateSchema)` (odstraní výchozí hodnoty).
- Nová oprávnění pro existující systémové role přidej do `PERMISSION_UPGRADES` (nová verze).
- Odpovědnost (vlastník procesu/rizika, RACI) vede na **funkční místo** (`positions`), ne na uživatele.
- Požadavky předpisů (ZKB, vyhl. 409/410, ISO 27001, DORA, NIS2 + 2024/2690, SOC 2, ISO 9001, CIS v8.1) jsou data v `shared/frameworks` (vlastní rámce jiných zemí = knihovna, ADR-079) se stabilním ID – při novele aktualizuj data, ID neměň bez migrace `requirement_assessments`/`control_requirements`. Texty ISO ani AICPA (SOC 2) nevkládej (autorské právo).
- Metodika rizik dle příl. 4 vyhl. 409: stupnice `scaleFor()`, `riskScore(policy, values, risk.scaleLevels)`.
  Jiné metodiky (OCTAVE, importované YAML/JSON/XML) jsou data `MethodologyDef` v registru (`shared/methodology.ts`);
  `riskScore` přepíná podle `methodologyKey` rizika, zbytkové hodnoty přes `residualValues()`. Vzorce jen přes `compileFormula/evalFormula`, nikdy `eval`.
- Skupina společností: každý dotaz nad daty společností přes `inScope` / `assertScope` / `targetCompany` (`auth/scope.ts`);
  nastavení společnosti přes `settingsFor` / `companySettings`; nová tabulka s daty společnosti = sloupec `company_id` (`companyRef()`).
- Procesy: kroky = zdroj pravdy, BPMN je volitelný (generátor `shared/bpmn.ts`). Rizika: skóre se nepersistuje, počítá `riskScore()`.
- Každá routa musí mít `requirePerm(...)` (hlídá `test/review.test.ts`, výjimky s kontrolou v handleru jen do `INLINE_GUARDED`); odpovědi API ani audit nesmí obsahovat hash ani pole `…Enc` (kontrola v integračních testech); nová oprávnění přidej do `PERMISSIONS` v `packages/shared/src/auth.ts` (+ `PERMISSION_GROUPS`, systémové role).
- Změny dat zapisuj do auditního logu (`audit()` z `auth/service.ts`).
- Routery používají `new Hono<AppEnv>()`; přihlášený uživatel: `currentUser(c)`, oprávnění: `hasPerm(c, …)`.
- Dokumenty ISMS (SoA, zpráva o rizicích, plán zvládání): neměnné snímky v `document_versions`, vykreslení `documents/render.ts` – vždy escapovat; schválené verze nemazat.
- Word export: `htmlToDocx` (`documents/docx.ts`) převádí jen podmnožinu HTML (h1–h3, p, div, table, ul/ol, b, br, span.muted/.small) –
  nové tiskové výstupy piš v ní (sdílené `printPage`, `html.esc` z `render.ts`), stažení přes `docxResponse`.
- Významné změny (§ 11): mezery počítá `changeGaps` ve `shared/isms.ts` (sdíleno API i UI); kritéria jsou v `settings.changeCriteria`.
- Incidenty: lhůty hlášení počítá `incidentDeadlines` (`shared/incidents.ts`) – nepersistovat; audity: `auditGaps`, `coverageState` (`shared/audits.ts`).
  Incident × SOC (ADR-056): podklady jen `socEvidenceFor`, návrh `socDraftFor` (`soc/incident.ts`, nic nezapisuje – převezme člověk do formuláře; `appendLines` / `mergeTimeline` bez duplicit); záznam o zvládání `incidentRecordHtml` (`incidents/record.ts`, tisk i Word).
